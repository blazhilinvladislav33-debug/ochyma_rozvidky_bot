# Вебпанель «Очима Розвідки»

Перша версія: Telegram-вхід, огляд станів публікацій і джерел, загальна пауза,
редактор дописів із JPG/PNG/MP4, чернетки, погодження, публікація зараз і розклад за Києвом,
особисті шаблони (створення, використання, редагування, видалення), звернення
з історією, текстовими відповідями, фото/відео, непрочитаними та станами діалогів.
Замовлення, статистика читачів, правила загроз і налаштування джерел
у цій версії залишаються в Telegram-боті. Журнал не змінено.

## Оновлення вже встановленого бота

1. Зупиніть бота: Host-Control.cmd від адміністратора → 3.
2. Зробіть резервну копію папки бота. Розпакуйте TelegramBot-update.zip у папку хоста,
   наприклад D:\TelegramBot-host, із заміною файлів. Чинні .env, .panel.env, база,
   Telegram-сесія та медіа цим архівом не замінюються.
3. Запустіть Update-Host.cmd від адміністратора: він встановить потрібні залежності,
   перевірить конфігурацію та запустить спільний процес бота й панелі.
4. На цьому ж ПК відкрийте http://127.0.0.1:8787. Без налаштування Telegram-входу
   приватні дані та команди недоступні. «Подивитися демонстрацію» показує лише
   вигадані приклади у браузері, без доступу до бази чи можливості змінити бота.

Нове встановлення: Install-Host.cmd встановлює залежності та один автозапуск
для бота й панелі. Host-Control: 1 — стан та адреса панелі, 2 — запуск обох,
3 — зупинка обох, 4 — спільний перезапуск. Після перезавантаження ПК їх запускає
наявне завдання Windows. WEB_ENABLED=0 у .panel.env вимикає лише панель.
Вебпанель працює окремо від повторних спроб з’єднання бота з Telegram.

## Чому потрібні дві адреси

GitHub Pages розміщує інтерфейс, наприклад https://LOGIN.github.io/bot-panel/.
Це адреса, яку ви відкриваєте на телефоні. GitHub Pages не запускає Python-бота
і не читає базу на вашому комп’ютері.

Друга адреса — HTTPS-доступ до вебсервера на вашому ПК. Він слухає тільки
127.0.0.1:8787. Потрібен налаштований HTTPS-проксі або захищений тунель на цю
адресу. Не відкривайте напряму порт із незахищеним HTTP в інтернет.
Домен купувати необов’язково, але зовнішня адреса має бути постійною: її
реєструють у Telegram. Тимчасова адреса, що змінюється після перезапуску,
потребуватиме повторної конфігурації та не підходить для постійного запуску.

Підключення тунелю не налаштоване автоматично: для цього потрібні вибраний
провайдер, його обліковий запис і зовнішня адреса. Якщо провайдер установлює
тунель як службу Windows, він також працює автоматично після запуску ПК.
Панель і бот уже мають спільний автозапуск; стороння служба тунелю керується
окремо засобами її провайдера. Не запускайте другу копію бота для панелі.

## Вхід через Telegram

Використовується Telegram OpenID Connect: код авторизації + PKCE, одноразовий
state, nonce і перевірка підпису RS256 через офіційні ключі Telegram.
Вхід через інший алгоритм у BotFather у цій версії не підтримується.
Офіційна інструкція: https://core.telegram.org/bots/telegram-login.

1. Після отримання зовнішньої адреси відкрийте BotFather → ваш бот → Login Widget.
2. Додайте Allowed URLs:
   - адресу інтерфейсу GitHub Pages;
   - точний redirect URI: https://АДРЕСА-СЕРВЕРА/auth/callback.
3. Отримайте Client ID та Client Secret. Це налаштування входу, а не BOT_TOKEN.
4. На серверному ПК запустіть Configure-Panel.cmd. Введіть адресу сервера,
   повну адресу панелі GitHub Pages та Client ID/Client Secret. Секрет вводиться
   приховано і зберігається тільки в .panel.env. Нікому його не надсилайте.
5. Перезапустіть Host-Control → 4.
6. Відкрийте GitHub-панель → «Увійти через Telegram». Якщо адреса сервера ще
   не підставлена, введіть її один раз. Вона не є секретом.

Доступ мають лише OWNER_ID, ADMIN_IDS, MODERATOR_IDS з чинного .env бота.
Модератор бачить свої дописи й передає їх на погодження. Власник та адмін
можуть публікувати, планувати й керувати загальною паузою. Шаблони особисті.
Зміна username не змінює права: перевіряється числовий Telegram ID на кожен
запит. Сеанс — 8 годин; вихід із панелі відкликає його на сервері.
У браузері зберігається токен сеансу в sessionStorage поточної вкладки;
у базі — лише його хеш. Коди входу, ID-токени та client secret не журналюються.
Окрема Telegram-сесія читання каналів не використовується для входу в панель.

## GitHub

Для завантаження використовуйте тільки TelegramBot-GitHub-source.zip:
він містить код, інтерфейс, інструкції й Pages workflow. Повний архів хоста
НЕ завантажуйте: він містить чинну базу та .env.

1. Створіть репозиторій bot-panel або використайте наявний. Доступність Pages
   для приватного репозиторію залежить від плану GitHub. Приватність даних
   забезпечується перевірками на сервері, а не приховуванням інтерфейсу.
2. Завантажте розпакований вміст GitHub-source архіву (включно з .github).
3. Settings → Pages → Source → GitHub Actions.
4. За бажанням: Settings → Secrets and variables → Actions → Variables →
   PANEL_API_URL = https://АДРЕСА-СЕРВЕРА. Це лише публічна адреса, без секретів.
5. Запустіть workflow Publish bot panel. Він публікує тільки web_ui.
   Код бота, .env, база та медіа на Pages не публікуються.
6. Впишіть отриману GitHub Pages адресу в Configure-Panel і Allowed URLs Telegram.

Зараз завантаження на GitHub не виконане: потрібен конкретний репозиторій
та доступ до нього. Workflow не встановлює оновлення на ваш ПК автоматично.
Оновлюйте хост архівом і Update-Host.cmd, зберігаючи чинні дані.

## Робота

- «Звернення» показує ті самі переписки, що й Telegram-бот, включно зі зверненнями
  за замовленнями. Є пошук, фільтр стану, непрочитані, історія й відповіді. Нові
  повідомлення та відповіді інших адміністраторів підтягуються кожні 5 секунд.
  У відповіді можна надіслати текст або одне фото/відео з підписом.
  Відкриття діалогу позначає показані повідомлення прочитаними для вашого ID.
  Модератори мають доступ до звернень, як у Telegram-боті; власні шаблони та
  дописи обмежені їхнім обліковим записом.
- Вкладення нових звернень можна завантажувати у браузері. Для старих вкладень,
  у яких збережено лише посилання на повідомлення, є «Отримати вкладення в Telegram»:
  бот надішле копію саме вам. Великі файли також відкривайте в Telegram.
- Закрите звернення спочатку відкрийте знову. Заблокованому користувачу відповіді
  не надсилаються. Після невизначеного результату надсилання панель не повторює
  відповідь автоматично: спершу перевірте історію в Telegram.

- Створити допис → текст/медіа → зберегти, опублікувати або запланувати.
- Текстовий редактор у першій версії працює з простим текстом. Незмінений
  текст зберігає наявне Telegram-форматування; після зміни тексту форматування
  скидається. HTML від користувача не виконується.
- Фото: JPG/PNG до 10 МБ; відео MP4 — до 49 МБ; до 10 вкладень. Медіа
  зберігаються в reader_media та входять у звичайний приватний архів хоста,
  якщо використовуються в дописах або шаблонах. У кодові архіви не входять.
- Попередній перегляд показує текст; кількість вкладень видно в редакторі.
  Наявні медіа Telegram у цій версії не завантажуються як мініатюри.
- Зберегти як шаблон → назва. У «Шаблонах» можна змінити текст, медіа,
  підписи, кнопки, назву, звук або видалити. Інші створені дописи не змінюються.
- Публікацію надсилає наявна черга бота. Загальна пауза й перевірки каналу
  продовжують діяти. Натискання не означає миттєвої доставки в Telegram.
- Панель не дозволяє повторне надсилання невизначених результатів: перевірте
  канал та поверніть допис через Telegram-бота після перевірки.
- Час у розкладі — Київ. Захист від застарілої редакції не дозволяє затерти
  зміни іншого редактора: після конфлікту відкрийте допис заново.

## Локальний перегляд оформлення

Для демонстрації без бота й даних: .venv\Scripts\python.exe web_panel.py,
потім http://127.0.0.1:8788/?demo=1. Цей запуск не підключається до Telegram,
не відкриває базу і не надає доступу до керування. Для робочого режиму
використовуйте лише Host-Control / host_runner.py.

# Читання сторонніх каналів через Telegram-акаунт

Бот може отримувати нові дописи з каналів через окремий користувацький акаунт Telegram. Адміністратор джерела не має додавати до нього вашого бота. Акаунт читання повинен бути підписаний на джерело й мати законний доступ до нього.

Модуль читає лише джерела, явно додані в боті. Він не надсилає повідомлень, не ставить реакцій, не підписується на канали й не позначає повідомлення прочитаними. Публікує у ваш канал саме бот. Вхід до Telegram створює звичайну активну сесію акаунта; технічні звернення до Telegram потрібні для роботи з'єднання.

## Підключення на хості

1. На новому хості спершу встановіть бота через `Install-Host.cmd` за HOST_README.md. Далі `Host-Control.cmd` від адміністратора → `3` — зупинити перед входом у акаунт. Якщо оновлюєте чинний хост, спершу зупиніть його, перенесіть оновлені файли та збережіть чинні `.env` і `tickets.sqlite3`.
2. На потрібному Telegram-акаунті в офіційному застосунку підпишіться на джерела. Для приватних каналів самостійно прийміть запрошення. За потреби надалі підписуйте акаунт на нові канали там само.
3. Отримайте власні **API ID** та **API Hash** на [my.telegram.org](https://my.telegram.org) → **API development tools**. Це дані Telegram-застосунку, а не токен бота. [Офіційна інструкція](https://core.telegram.org/api/obtaining_api_id).
4. Запустіть `Connect-Reader.cmd` саме на хості. Уведіть API ID, API Hash, номер акаунта, код входу та пароль двоетапної перевірки, якщо він є. Секретні поля під час введення не показуються. Коди та паролі в чат бота не надсилайте.
5. Після успішного входу вікно покаже канали акаунта з посиланнями або числовими ID. Закрийте вікно.
6. Запустіть бота: `Host-Control.cmd` → `2`. Якщо це перше встановлення — використайте `Install-Host.cmd`.
7. У боті: **Канали → Джерело через акаунт**. Надішліть, наприклад, `@sumyliketop` або його посилання. Для приватного каналу використайте ID зі списку у вікні підключення.
8. Додайте бота адміністратором вашого каналу з правом публікації. Якщо канал ще не вибрано, бот автоматично підключить його за подією додавання, виконаною власником або адміністратором бота. Усі нові дописи використовують цей єдиний канал. Якщо бот уже був адміністратором до оновлення, виберіть канал один раз через **Канали → Підключити мій канал**. Додавання бота до другого каналу не замінює поточний; змінити його можна через **Канали → Змінити мій канал**. Раніше погоджені дописи після зміни каналу повертаються на перевірку; канал у них потрібно застосувати кнопкою «Канал» і погодити знову.
9. Перевірте підписи зверху та знизу й увімкніть автопублікацію. У картці кожного джерела виберіть **Публікувати одразу**, якщо потрібне автоматичне надсилання. Нові джерела початково йдуть на погодження.

Для наступного джерела повторюйте підписку акаунтом і додавання джерела в боті. Повторний вхід у Telegram для кожного каналу не потрібен. Якщо щойно доданий приватний канал не знаходиться за ID, перезапустіть бота для оновлення переліку каналів.

## Що відбувається з дописами

- Читання починається з нових дописів після додавання джерела. Старий архів каналу не копіюється.
- Нові події пробуджують читання, також є перевірка приблизно кожні 3 секунди. Завантаження медіа, інтернет і обмеження Telegram можуть збільшити затримку; одночасна публікація до секунди не гарантується.
- Після втрати з'єднання модуль повторює підключення та дочитує доступні дописи після збереженого номера. Новини старші 15 хвилин повертаються на погодження замість автоматичної публікації як свіжих.
- Працюють підписи, фільтри, погодження, пошук повторів і загальна пауза. Текст надходить без вихідного форматування; посилання, написані в самому тексті, залишаються.
- Підтримуються фото, відео, анімації, документи, аудіо та голосові; фото до 10 МБ, інші вкладення до 49 МБ. Альбоми збирає наявна черга; запізнілі частини зберігаються окремо на перевірку. Захищені дописи, службові повідомлення та непідтримувані вкладення не публікуються; причина відображається в помилках.
- Зміни й видалення дописів у джерелі автоматично у вашому каналі не повторюються. Для виправлення використовуйте редактор публікацій у боті.
- Вкладення зберігаються у `reader_media`. Ліміт сховища — 1 ГБ, після досягнення нові медіа позначаються помилкою. Не видаляйте файли, які потрібні чернеткам, погодженню або повторній публікації.

## Зупинка й захист сесії

**Канали → Читання акаунтом** зупиняє отримання нових дописів і повертає його автоматичну чергу на погодження. Звернення та замовлення працюють далі. Для повного відключення акаунта зупиніть бота й завершіть сесію **Information Channel Reader** у Telegram → Пристрої. Після цього видаліть локальну папку `.reader`, якщо хочете підключити інший акаунт.

Сесія й API-дані зберігаються в `.reader`. Сесія надає доступ до акаунта: не передавайте й не публікуйте цю папку. Звичайний архів перенесення не включає її; на іншому хості потрібно ввійти заново. Коди входу та пароль двоетапної перевірки модуль не зберігає. Використовуйте правила доступу Windows до папки хоста та вимоги [Telegram API](https://core.telegram.org/api/terms).

Без ваших API-даних та локального входу акаунт залишається непідключеним. Наявні джерела через бота продовжують працювати.

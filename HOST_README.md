# Перенесення бота на Windows-хост

Читання каналів через окремий Telegram-акаунт: [READER_README.md](READER_README.md). Контроль джерел, шаблони й уточнення: [CHANNEL_FEATURES.md](CHANNEL_FEATURES.md).

Правила загроз, стиль, таймери та ручні дописи: [ALERT_RULES_README.md](ALERT_RULES_README.md). Для оновлення чинного хоста використовуйте `TelegramBot-update.zip`: він не містить `.env`, бази чи сесії акаунта. Зупиніть бота, зробіть резервну копію, замініть файли з архіву й запустіть бота знову.

Пакет налаштований для Windows 10/11 або Windows Server із Планувальником завдань. Після встановлення бот працює у фоні та запускається після завантаження Windows, без входу на робочий стіл.

## 1. Підготуйте актуальний архів

1. Зупиніть бота на старому ПК. Якщо він запущений у вікні — натисніть Ctrl+C. Якщо вже встановлений як хост — відкрийте `Host-Control.cmd`, виберіть `3`.
2. Запустіть `Refresh-Bundle.cmd` у папці бота.
3. Скопіюйте отриманий `dist\TelegramBot-host.zip` на хост. Розпакуйте, наприклад, у `C:\TelegramBot`.

Архів містить токен бота, налаштування та знімок бази звернень, замовлень і публікацій на момент створення архіву. Зберігайте його приватно. Не публікуйте архів і не передавайте стороннім. Старий бот після перенесення повинен залишатися вимкненим: один токен має працювати тільки на одному ПК.

Збережені вкладення джерел, на які посилається база, також входять до архіву. Авторизована сесія Telegram-акаунта з папки `.reader` не переноситься — підключіть акаунт на новому хості через `Connect-Reader.cmd`.

## 2. Встановіть на хості

1. Встановіть [Python для Windows](https://www.python.org/downloads/windows/) версії 3.12, 3.13 або 3.14. Під час встановлення увімкніть додавання Python до PATH. Перевірено на Python 3.14.

   Якщо також установлений Python 3.15, видаляти його не потрібно. Установіть Python 3.14 разом із Python Launcher: інсталятор бота шукає спершу 3.14, потім 3.13 та 3.12. Якщо `.venv` уже створена з іншою версією, зупиніть бота й перейменуйте цю папку, наприклад на `.venv-old`, перед повторним установленням.
2. Підключіть інтернет. Натисніть правою кнопкою на `Install-Host.cmd` → **Запустити від імені адміністратора**.
3. Дочекайтеся встановлення залежностей і перевірки бази.
4. У вікні облікових даних укажіть користувача Windows і його **пароль, не PIN**. Рекомендовано той самий обліковий запис, під яким установлений Python. Потрібен обліковий запис із паролем.
5. Дочекайтеся повідомлення `DONE`. Бот одразу запуститься у фоні.

Пароль передається Планувальнику Windows; у файлах бота він не зберігається. Завдання `TelegramBot-Host` запускає бота з обмеженими правами вибраного користувача. Папка повинна бути на локальному диску NTFS, а не на флешці чи мережевому диску.

## 3. Перевірте роботу

1. Напишіть боту в Telegram і перевірте відповідь.
2. Перезавантажте хост. Перевірте відповідь бота ще до входу на робочий стіл Windows.
3. Тимчасово вимкніть інтернет, потім увімкніть. Після відновлення з'єднання бот має знову відповідати; повторні спроби можуть тривати близько хвилини.

При втраті інтернету бот повторює підключення. При помилці запуску або аварії він запускається повторно. Журнал обмежений за розміром і зберігається у `logs\bot.log` та його попередніх копіях. Тривала відсутність зв'язку може призвести до втрати старих оновлень на стороні Telegram — пакет не гарантує отримання всіх подій за будь-який час простою.

## Керування

Відкрийте `Host-Control.cmd` **від імені адміністратора**:

- `1` — стан і останні записи журналу.
- `2` — увімкнути автозапуск і запустити бота.
- `3` — зупинити бота й вимкнути автозапуск до наступного вибору `2`.
- `4` — перезапустити й увімкнути автозапуск.
- `5` — видалити автозапуск. База й файли залишаться.

Якщо зміните пароль Windows або перемістите папку, повторіть установлення. Перед переміщенням видаліть старе завдання через пункт `5`. Не переносіть `.venv` з іншого ПК: інсталятор створює її сам.

## Живлення хоста

У параметрах живлення Windows вимкніть автоматичний сон і гібернацію хоста. Вимкнення екрана дозволене. Коли ПК вимкнений або спить, бот не працює. Для відновлення після зникнення електрики сам ПК має вміти автоматично вмикатися після повернення живлення — це окреме налаштування BIOS/UEFI.

На комп'ютері, де цей пакет підготовлено, автозапуск автоматично не встановлюється. Він з'явиться лише після запуску інсталятора на обраному хості.
# Швидка публікація після оновлення

Керування власними шаблонами: «Публікації → Шаблони повідомлень → назва шаблону». Доступні використання, редагування тексту/медіа/підписів/кнопок/звуку, зміна назви та видалення з підтвердженням. Після редагування натисніть «Зберегти зміни шаблону». Видалення або редагування шаблону не змінює вже створені чи опубліковані дописи. Шаблони особисті для кожного редактора.

Нові пропозиції читачів публікуються у форматі «Нам пишуть:» та тексту без місця й часу; ці відомості зберігаються в заявці для команди. Під дописом — посилання «Канал» і «Бот». Для каналу використовується його публічне посилання або наявне посилання-запрошення; якщо обох немає, бот попросить налаштувати посилання перед публікацією. Для альбомів кнопки надсилаються окремим повідомленням після вкладень. Раніше створені дописи автоматично не переписуються.

Головне меню «Публікації» показує лише розділи. Окремі дописи відкриваються після вибору «Чернетки», «Опубліковані» тощо. Щоб зберегти власний шаблон: відкрийте готовий допис → «Додатково» → «Зберегти шаблон» → введіть назву. Він зберігається у вашій бібліотеці «Шаблони повідомлень» незалежно від статусу вихідного допису. Кожне використання створює нову чернетку з поточним каналом; перед надсиланням перевірте актуальність тексту, дат і місць. Шаблони зберігаються в tickets.sqlite3; не замінюйте цю базу при оновленні.

У редакторі основні дії показані одразу, а підписи, URL-кнопки, звук, застосування поточного каналу, копіювання та архів — через «Додатково». Адміністратор створює допис, надсилає текст або одиночне фото/відео та натискає «Опублікувати зараз» без повторного підтвердження. Перегляд залишається окремою необов’язковою кнопкою. Для альбому натисніть «Готово» після всіх вкладень. Розклад потребує підтвердження дати, а модератор надсилає допис на погодження. Загальна пауза публікацій діє і для цього способу.

# Вебпанель

Після оновлення запустіть Update-Host.cmd від адміністратора для встановлення нових залежностей. Бот і вебпанель запускаються одним завданням Host-Control. Докладні кроки входу через Telegram, GitHub Pages та підключення HTTPS-адреси серверного ПК — у WEB_PANEL_README.md. Звернення у панелі працюють із тими самими повідомленнями, що й Telegram-бот. Зміна журналу не входила в це оновлення.
